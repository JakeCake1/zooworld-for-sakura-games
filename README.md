# Zoo World

A small top-down Unity simulation created for the Sakura Games test task. Frogs jump, snakes move continuously, animals collide through 3D physics, predators eat other animals, and the HUD counts dead prey and predators.

## Quick start

1. Open the project in Unity `6000.3.25f1`.
2. Open `Assets/Game/Scenes/Main.unity`.
3. Press **Play**. No input is required.

## Requirements

- Unity `6000.3.25f1`
- Windows, macOS, or Linux Editor
- Internet access during the first package restore for VContainer

## Architecture

The top-level ownership is explicit:

```text
Assets/
├── Game/Features
│   ├── Animals/Common
│   ├── Animals/Frog/{Scripts,Content}
│   ├── Animals/Snake/{Scripts,Content}
│   ├── FoodChain
│   └── Spawning
├── Ui/Hud
└── Services/{Assets,Configuration,Composition}
```

- `Animal` contains only common lifecycle, collision, camera-boundary, and death behavior.
- `AnimalMovementRunner` owns the fixed-step UniTask loop; animal MonoBehaviours have no `Update` or `FixedUpdate` movement loop.
- `Frog`/`Snake`, their DTOs, definitions, movement implementations, and content live in their species folders.
- The common `AnimalConfigDto` contains only `Id`, `FeedingType`, `SpawnWeight`, and `PrefabAddress`. Jump data exists only in `FrogConfigDto`; linear speed exists only in `SnakeConfigDto`.
- `FoodChainRules` is a pure domain rule set. It contains no Unity API and is covered by EditMode tests.
- `FoodChainService` resolves each physics pair once per frame and applies the domain result.
- `ZooWorldLifetimeScope` is the VContainer composition root.
- `IAnimalAssetProvider` isolates Addressables from the factory and owns instance release.
- `DeathStatistics` is observable state consumed by `HudView`.
- DOTween drives frog jumps and the `Tasty!` feedback.

Predator-versus-predator encounters use a deterministic rule: the animal spawned first survives. This keeps the behavior simple and testable.

## Code convention

When a method contains two or more statements that implement one logical operation, extract that operation into a small, intention-revealing method. Constructors and flat value mapping are kept together when splitting them would hide rather than clarify the data contract.

## Replacing ScriptableObject data

Species `AnimalDefinition` assets are not gameplay models. They are authoring formats converted to storage-independent DTOs through `IAnimalConfigSource`.

To move the data to JSON, a remote config, or a database:

1. Implement `IAnimalConfigSource`.
2. Deserialize/map the external representation into `FrogConfigDto`, `SnakeConfigDto`, or another species DTO.
3. Replace the source registration in `ZooWorldLifetimeScope`.

No movement, spawning, food-chain, Addressables, or UI code needs to change. `AnimalCatalogTests` demonstrates this boundary with a non-ScriptableObject source.

## Adding an animal

Use the Create Asset workflow:

1. In the Project window, right-click `Assets/Game/Features/Animals`.
2. Choose `Create > Zoo World > Animal...`.
3. Enter a valid C# class name and click **Create Animal Feature**.
4. Wait for Unity to compile the generated scripts. The created Definition asset is selected when authoring finishes.
5. Configure its feeding type, spawn weight, and any species-specific movement fields in the Inspector.

The editor creates the full species set:

- `<Animal>/Scripts/<Animal>.cs`
- `<Animal>/Scripts/<Animal>ConfigDto.cs`
- `<Animal>/Scripts/<Animal>Definition.cs`
- `<Animal>/Scripts/<Animal>Movement.cs`
- `<Animal>/Content/<Animal>.mat`
- `<Animal>/Content/<Animal>.prefab`
- `<Animal>/Content/<Animal>Definition.asset`

The prefab is a configured cube using the same base proportions as Frog. Complete the species-specific DTO and movement when custom behavior is needed; no switch in `Animal` needs to be changed.

Generated Definition classes also include `CreateAssetMenu`, so additional Definition assets appear under `Create > Zoo World > Animals`. The generated prefab receives an `animals/<id>` address, while every created `AnimalDefinition` is automatically marked Addressable with the `animal-definition` label. The runtime catalog loads that label asynchronously, so the new configured species joins weighted spawning without editing the scene or composition root.

The current demo is reproducibly generated by `Zoo World > Rebuild Demo Content`. It creates a brown ground, green and red cube animals, species configs, scene, and Addressables entries.

## Tests

- EditMode tests cover prey/predator rules, deterministic predator encounters, death counters, and species-data separation.
- A PlayMode smoke test loads `Main`, verifies the VContainer scope, and checks the brown ground.

Run both suites from `Window > General > Test Runner`.
