# Zoo World

A small top-down Unity simulation created for the Sakura Games test task. Frogs jump, snakes move continuously, animals collide through 3D physics, predators eat other animals, and the HUD counts dead prey and predators.

## Requirements

- Unity `6000.3.25f1`
- Windows, macOS, or Linux Editor
- Internet access during the first package restore for VContainer

Open `Assets/ZooWorld/Scenes/Main.unity` and enter Play Mode. No input is required.

## Architecture

The gameplay is split by responsibility rather than by animal species:

```text
AnimalDefinition (authoring only)
        |
ScriptableObjectAnimalConfigSource
        |
AnimalConfigDto <- domain and gameplay depend on this type
        |
AnimalCatalog -> AnimalSpawner -> AnimalFactory
                                  |
                         Addressables provider
                                  |
                              AnimalActor
                         / movement strategy \
                    JumpMovement          LinearMovement
```

- `FoodChainRules` is a pure domain rule set. It contains no Unity API and is covered by EditMode tests.
- `FoodChainService` resolves each physics pair once per frame and applies the domain result.
- `IAnimalMovement` is a Strategy. A new locomotion type does not change spawning, UI, or food-chain code.
- `ZooWorldLifetimeScope` is the VContainer composition root.
- `IAnimalAssetProvider` isolates Addressables from the factory and owns instance release.
- `DeathStatistics` is observable state consumed by the uGUI presenter.
- DOTween drives frog jumps and the `Tasty!` feedback.

Predator-versus-predator encounters use a deterministic rule: the animal spawned first survives. This keeps the behavior simple and testable.

## Replacing ScriptableObject data

`AnimalDefinition` is not used as a gameplay model. It is an authoring format converted to immutable-facing `AnimalConfigDto` instances through `IAnimalConfigSource`.

To move the data to JSON, a remote config, or a database:

1. Implement `IAnimalConfigSource`.
2. Deserialize/map the external representation into `AnimalConfigDto` objects.
3. Replace the source registration in `ZooWorldLifetimeScope`.

No movement, spawning, food-chain, Addressables, or UI code needs to change. `AnimalCatalogTests` demonstrates this boundary with a non-ScriptableObject source.

## Adding an animal

1. Create an addressable prefab with `AnimalActor`, a collider, and a rigidbody.
2. Create an authoring definition, or add the equivalent record to another `IAnimalConfigSource`.
3. Reuse an existing `MovementKind`, or add one new `IAnimalMovement` strategy and map it in `AnimalActor.CreateMovement`.

The current demo content is reproducibly generated by `Zoo World > Rebuild Demo Content`. The generator creates the scene, primitive prefabs, configurations, and Addressables entries.

## Tests

- EditMode tests cover prey/predator rules, deterministic predator encounters, death counters, and the DTO source boundary.
- A PlayMode smoke test loads `Main`, constructs the VContainer scope, loads a prefab through Addressables, and verifies that an animal spawns.

Run both suites from `Window > General > Test Runner`.
